已完成 **50/50 题**的 native Search 离线审计，覆盖 **248 个原生 query slot、247 个成功 query、251 份已有 native 请求尝试文件**。Q18/Q28 各只有4条 native；Q40 q3 原来就失败，本阶段未重试。

**结果层出现了比 query-text coverage/Jaccard 更明显的描述性倾向：正例平均重复更多、unique 候选更少、末条 native 的新增候选更少。但分布仍明显重叠，尚不存在能可靠区分这5题的简单规则。** 这提供了“检索是否趋于饱和”的输入侧线索，不能等同于“第6条 Anchor 必然带来 GT”。

另外，原问题核心任务并没有在5个正例的所有 native results 中消失。尤其 **Q48 的因子挖掘已由一篇 native 候选体现；Q28 的三个参照 benchmark 也都重新出现**。应从“全遗漏”转向观察“独立候选支撑是否稀薄、重复是否严重、结果是否偏向相邻任务”，同时承认这些现象也有无收益反例。

## 数据、特征与边界

- 只使用已有 `QUERY_PLANNER_V1_2_SEARCH_AB_001.json` 的 native 字段及对应 q1–q5 raw response 文件。未使用 Anchor response、GT 标题/ID、matched GT、论文 metadata 或全文来计算特征/写结果内容判断；收益对照仅采用用户给定的5个 QID。
- 原文元素和 H 标记直接继承上一阶段177项。先生成并保存无标签 `native_feedback_features.json`，再保存逐题内容复核，最后连接事后标签。已知正例名单，因此不是盲审；也不能把这些人工判断当成独立金标准。
- raw response 的已有 SHA256、结构化响应和原始 candidate parser 输出逐一核对。未改变解析规则，未重新运行 evaluator。成功结果共2466个 organic hits，全部按原 parser 得到 arXiv ID；每 query 内去重后共2326个 ID membership；每题再取 union 共1445个 `(QID, arXiv ID)`，跨全部题全局去重为1154个 ID。这几个分母不同，不能混用。
- 设每 query 的 unique ID 集合为 `S_i`：pair Jaccard=`|S_i∩S_j|/|S_i∪S_j|`；overlap coefficient=`|S_i∩S_j|/min(|S_i|,|S_j|)`。重复比例=`1−|∪S_i|/Σ|S_i|`，排除同一query内重复。ID不同时，即使标题相似也不合并。
- 每 query 同时报告 **相对其余所有query的独有数** `|S_i−∪(j≠i)S_j|` 和 **按原序新增数** `|S_i−∪(j<i)S_j|`。前者无顺序偏差，后者描述native原序扩张。不能把它们与新增GT数混淆。第5条的二者相等；前几条一般不同。
- Q40 q3 为缺测：主 pair 平均只用成功query对，另存全slot版本；其独有数0表示没有可用数据，不能解释为一次成功的无增量检索。对相同5条预算和全部成功子集另做描述性敏感性统计。
- 每个元素报告严格短语匹配、同一title+snippet中的内容token共现、unique ID数、query位置及原始证据。严格匹配只做小写字母数字分词；token版去固定通用词并做浅层复数归一。**两者都不是语义蕴含判断**，不自动展开缩写，不将多个论文的组件拼成完整关系。
- 每题另做核心任务/方法及主题内容复核：`visible`表示至少有清楚的核心任务例子，**不表示全部约束满足**；`partial`表示附近主题/组件存在，而决定性组合或限制尚未得到明确展示。表中注明具体证据和边界，未将这种审计标注实现为运行时判定器。
- 主题集中度用去重论文的title+snippet平均词面Jaccard及高频词作代理，每ID取native原序首次片段；同ID其他query的片段全部保存在JSON并用于元素检索。此代理受片段截断、措辞及领域词影响，不能等同于语义聚类。逐题文字分析补充其局限。

### Q28与Q48：分散偏题 vs 窄任务候选稀薄

**Q48不是因子挖掘零覆盖。** 全部native title/snippet中可见的明确因子挖掘候选是`2406.10811 LLMFactor: Extracting Profitable Factors...`，在q1/q3/q5各出现一次；q5:r8片段进一步写明identify factors。虽然`mining factors`严格匹配和token共现均为0，直接同义任务已出现。因此应描述为 **19个unique中有1个清楚的窄任务证据，3次命中仍只是一篇独立论文**，而非3份独立覆盖。`2407.18957`片段的external factors只说交易影响因素，不能冒充因子挖掘方法。

Q48其余候选多围绕金融综述、股票预测、交易和通用模型应用；5条query重复比例59.57%，q5的9个unique全部已在q1–q4出现。它支持的输入侧假设是：**检索围绕大领域重复，窄任务虽有命中但独立候选支撑薄弱**。Anchor可能带来另一种窄任务措辞，不过这不是收益保证；此解释不使用任何Anchor结果或GT论文内容。

**Q28也不是三个benchmark在结果里全遗漏。** `q1:r1 / 2408.16498`提HumanEval，`q2:r7 / 2404.06041`同时提HumanEval/MBPP，`q2:r2 / 2403.04814`明确提CodeContests。严格规则把`code_contests`切成两个token，所以漏掉CamelCase写法；人工复核已注明该例，不为结果重新调整自动匹配规则。

Q28欠缺的是“比HumanEval和MBPP更难、比CodeContests更容易”的**完整目标关系**。q3有10个候选全是相对其他queries独有，包含VisEval、PyHard、ALLSH、数学/中文考试等难度结果。这个较高新增量没有直接证明目标区间覆盖更好；它也可能来自`hardness`把主题带向别的评估领域。

因此两题在结果层的差别比query层更具体：Q48是**低新增量、重复的大领域结果，加上薄弱但真实的因子任务支撑**；Q28是**低重叠、局部扩散及未得到明确展示的比较关系**。这可以解释为什么两者不应只按“约束遗漏数”归为同一类型，**不能仅凭此反推出Q28的Anchor必然无益**。本阶段只将它的无收益标签作为事后对照，没有读取其Anchor结果。

## 可在native Search后计算的候选方向

1. **观察候选扩张是否趋于饱和。** 使用结果ID pair Jaccard、重复比例、各query leave-one-out独有数与原序新增数，尤其末条新增量。这些量不需要GT或LLM，已在本阶段作为审计统计计算；“据此追加Anchor”的决策没有实现。它比文本Jaccard更贴近实际检索多样性，也是本批较有依据的候选方向。Q6/Q11/Q26说明高重复仍可能只是正常地找到同一主题，不能单独作为收益规则。
2. **同时考察窄任务的独立候选支撑与大领域重复。** 原问题中已定义的核心任务，在多少个不同arXiv ID的可见文本中得到直接或明确同义体现；同一篇被多个query命中不重复计数。Q48是例子。不得把严格原短语缺失当作语义缺失，也不得事后用GT论文里的术语定义“核心”。本阶段只有人工证据复核，没有实现可自动部署的语义判定器或触发阈值。
3. **把主题漂移和关系未体现作为诊断信息，而非单独的加Anchor规则。** 可以从同一hit是否共同体现任务/方法/对象、query特有候选的标题主题、比较参照与目标关系是否混淆来观察。Q28的10个独有q3结果、Q44的Crypto歧义说明“更多unique”也可能偏离任务。这类信号适合解释检索问题；现有无收益反例多，不能声称它能决定第6次Search是否划算。

这三项只作为候选规律，没有组合成分类器、没有为本批5个正例挑阈值、没有输出“应该追加Anchor”的触发名单。重复比例、union大小、Jaccard和新增数彼此相关，不能当成四份独立证据；仅5个正例也不足以确定稳定的收益预测能力。

**最终判断：Search-result层有更清楚的“候选重复/新增不足”描述性信号，优于本批query-text层几乎无差别的观察；但仍没有可直接采用的Selective Anchor规则。结果任务全无并非5个正例的共同点，词面缺失与语义缺失必须分开。**
